How the ledger is built, end to end

A household expense tracker for Indian families. A React app on S3 and CloudFront calls a FastAPI app on Lambda through API Gateway. Cognito handles sign-in and DynamoDB stores the data. The infrastructure is AWS CDK in Python. This page is the visual companion to the repository README.

Design decisions

Compute

One Lambda for the whole API

Routing happens inside FastAPI. One function keeps deploys simple and means only one cold start.

Auth

Tokens are checked at the gateway

The JWT authorizer rejects bad tokens before Lambda runs. Route code only asks who the caller is.

Storage

Single-table DynamoDB

Every read is one partition, PK = USER#<sub>, so no secondary indexes are needed.

Files

Receipts skip Lambda

The browser uploads and downloads directly from S3 with 5-minute presigned URLs scoped to the caller.

Secrets

Not in git, not in templates

CDK emits {{resolve:secretsmanager:…}} references. CloudFormation fills them in at deploy time.

Public routes

Two literal routes skip auth

/health and /whatsapp/webhook take precedence over the authorized /{proxy+} catch-all.

Life of a request

What happens between a click and a DynamoDB read. Step 3 is the security gate: the Lambda never sees a request that failed it.

1

Get a token

Amplify returns the Cognito ID token, refreshing it if needed.

fetchAuthSession()
2

Call the API

The only HTTP client sends Authorization: Bearer.

services/cloudApi.ts
3

Gateway verifies

Signature, issuer = user pool, audience = app client. Fail → 401.

HTTP API JWT authorizer
4

Who is it?

Mangum hands off to FastAPI; the verified sub claim is the user id.

dependencies/auth.py
5

Read the partition

Query USER#<sub>, return camelCase JSON.

routers/* → db.py

Why the ID token and not the access token? The HTTP API authorizer checks aud against the app client id, and only Cognito's ID token carries aud.

Removal policy

Outside prod, the table, buckets and user pool are DESTROY and buckets auto-empty, so cdk destroy removes everything. In prod they are RETAIN.

/whatsapp/webhookPOSTnoneTwilio calls it; the app checks X-Twilio-Signature itself

OPTIONS is not routed on purpose. API Gateway's built-in CORS responder answers preflights. Routing ANY would push preflights through the authorizer and break every cross-origin request.

Docker-free bundling stacks/local_bundling.py

The Lambda package is built without Docker: pip install --platform manylinux2014_x86_64 --only-binary=:all: --python-version 3.12 into the asset folder, then the API source is copied in. Every dependency in api/requirements.txt must therefore ship a manylinux wheel. Pure-Python packages are fine.

Signature check

HMAC-SHA1(authToken, fullUrl + key+value of every form field, sorted), base64-encoded, compared in constant time with X-Twilio-Signature.

Message parsing

The first number is the amount (it may start with ₹, rs or inr). The rest is the description. A keyword table picks the category: auto → auto_rickshaw, petrol → fuel, dinner → dine_out, otherwise other.

Why two link items?

The webhook knows only the phone; the app knows only the user. Writing both directions makes each lookup a single GetItem without a GSI.

At a few thousand items per user a full-partition query is well within limits. If a user ever grows very large, a date-sortable key such as EXPENSE#<isoDate>#<uuid> would allow range queries.

§12

Local development

Needs Node.js 20+, Python 3.12+, and the AWS CLI v2 for deploys. Pick the mode that matches the work.

The deployed API and Cognito already allow http://localhost:5173, so no backend setup is needed. You sign in with a real account and read and write real dev data.

cd frontend
npm install
npm run dev:aws        # http://localhost:5173/ — root path matches the Cognito callback URLs

Use dev:aws, not dev. Plain dev serves under /ExpenseTrack-Pro/, so a Google or Facebook redirect back to localhost:5173/ misses the app.

FastAPI under uvicorn against a local DynamoDB. boto3 honours AWS_ENDPOINT_URL_DYNAMODB, so no code changes are needed.

# 1) local DynamoDB (or: pip install "moto[server]" && moto_server -p 8001)
docker run -d -p 8001:8000 amazon/dynamodb-local

# 2) fake credentials, point boto3 at it
export AWS_ACCESS_KEY_ID=local AWS_SECRET_ACCESS_KEY=local AWS_DEFAULT_REGION=ap-southeast-2
export AWS_ENDPOINT_URL_DYNAMODB=http://localhost:8001

# 3) same key schema as the CDK table
aws dynamodb create-table --endpoint-url http://localhost:8001 \
  --table-name expense-track-pro-local \
  --attribute-definitions AttributeName=PK,AttributeType=S AttributeName=SK,AttributeType=S \
  --key-schema AttributeName=PK,KeyType=HASH AttributeName=SK,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST

# 4) run the API
cd backend/api
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt uvicorn
TABLE_NAME=expense-track-pro-local STAGE=dev uvicorn main:app --reload --port 8000
# X-Local-User-Id stands in for a signed-in user (never accepted in prod)
curl localhost:8000/health
curl -H "X-Local-User-Id: test-user" localhost:8000/expenses
curl -X POST -H "X-Local-User-Id: test-user" -H "Content-Type: application/json" \
  -d '{"date":"2026-10-09T00:00:00Z","amount":250,"category":"grocery","description":"Weekly groceries"}' \
  localhost:8000/expenses

The frontend can't point at the local API as-is: it always sends a Cognito token to the hard-coded API_BASE_URL. Use mode A for UI work and mode B for API work. Receipts need a real bucket; the webhook needs a token and a correctly signed request.

No automated test suite yet. Deploys are CDK change sets; a failed stack update rolls back automatically.

Watch for replacements in Auth and Data. A new user pool means every user signs up again; a replaced table loses its data outside prod. If cdk diff shows [-]/[+] with “replace”, stop and rethink.

First-time setup

  1. AWS access

    aws login --region ap-southeast-2, or an IAM key limited to sts:AssumeRole on cdk-hnb659fds-* plus secretsmanager:*Secret* on expense-track-pro/*. Check with aws sts get-caller-identity.

  2. Install tools

    npm i -g aws-cdk, then a venv in backend/cdk with pip install -r requirements.txt.

  3. Bootstrap CDK

    cdk bootstrap aws://<account>/ap-southeast-2, once per account and Region.

  4. Create the three secrets

    The Auth and Api stacks fail to deploy without them (see §11).

  5. Build the frontend

    cd frontend && npm ci && npm run build:aws. The Frontend stack uploads dist-aws.

  6. Deploy everything

    cdk deploy --all for dev, or add -c stage=prod for a separate prod copy.

  7. Wire up the outputs

    For a new pool or API, update amplify.ts, API_BASE_URL and the origin lists, then redeploy the Frontend stack.

  8. External consoles

    Add the /oauth2/idpresponse URL in Google and Facebook, add the Facebook email permission, set the Twilio webhook.

  9. Confirm the SNS subscription

    Click the link in AWS's email, or alarms are never delivered.

Monitoring

Five alarms on SNS topic expense-track-pro-alerts-<stage>, delivered by email. Missing data counts as not breaching, so quiet periods stay quiet.

Cost

Everything is pay-per-use, so an idle stage costs close to nothing. Watch Secrets Manager (about $0.40 per secret per month), Cognito MAUs past the free tier, and Twilio once off the trial.

Account constraints

Regional resources must be in ap-southeast-2: no Lambda@Edge, StackSets or cross-Region replication. Sudden AccessDenied usually means the project's spend limit was hit.

§16

Known limits & tech debt

What to fix before a real launch.

  • No automated tests or CI.
  • Old TypeScript and ESLint errors; npm run build fails, build:aws skips the type check.
  • Pool ids and API URL are hard-coded instead of injected per stage with import.meta.env.
  • Cognito's default sender is capped at 50 emails a day; move to SES.
  • Tokens live in localStorage. Consider cookie storage, shorter lifetimes and refresh-token rotation.
  • No GSIs or date-sorted keys; loading a ledger is a full-partition query.
  • Receipt uploads aren't size-limited or checked after upload.
  • WhatsApp runs on Twilio's trial sender (5 numbers), and the real Auth Token isn't stored yet.
  • No custom domain; the site uses the CloudFront default.
  • Old GitHub Pages scripts and the /ExpenseTrack-Pro/ base path still exist.
